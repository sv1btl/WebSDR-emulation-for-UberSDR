1What you get

This package replaces the page UberSDR serves on its WebSDR port (8901) with the classic Twente WebSDR interface, restyled by RW3PS and adapted to UberSDR's Opus sound engine.

  • Waterfall with colours and automatic brightness and contrast.
  • Spectrum in the PhantomSDR style, over the waterfall or above it ("spectrum + waterfall", the default for first-time visitors).
  • A 3D spectrum as in PhantomSDR-Plus, with the waterfall's own colours (the 3D switch next to "Tube & Waterfall & DSP & Audio"; details).
  • Click-to-tune on the waterfall and spectrum, rounded to 0.5 kHz.
  • Signal readouts on the radio display, as in PhantomSDR-Plus: dBm, dBµV, SNR and NF (noise floor) in a row over the S-meter.
  • Digit tuning on the frequency display: mouse wheel over a digit, left click up, right click down.
  • Frequency keypad: click anywhere else in the black frequency / S-meter frame (desktop page) for a number pad with a decimal point; type the frequency in kHz and press Enter (details).
  • Band buttons that zoom to the band and follow the frequency; All shows the whole receiver range and stays lit while the waterfall is fully zoomed out. As in PhantomSDR-Plus, each band button remembers the last frequency tuned in that band, here with its mode and filter too (kept in the visitor's browser); a second press on the band already lit goes back to the band's default.
  • More Mode buttons: RADE V1 (FreeDV digital voice, RADEL and RADEU), decoded by UberSDR's own FreeDV extension; IQ (the raw I/Q, with IQ recording) and DRM (decoded by UberSDR).
  • The desktop page fits the browser window: it is scaled to the window's width, from 1024 px screens to 4K (add ?nofit to the address to switch this off).
  • A dark theme for the whole page (the Light GUI / Dark GUI switch next to Auto brightness; the original light look is the default, each visitor's choice is kept).
  • A CW decoder window that opens under the Mode buttons while the mode is CW, using PhantomSDR-Plus's CW decoder in the listener's browser.
  • Digital-mode decoders from PhantomSDR-Plus (FT8, FT4, FT2, JS8, WSPR, SSTV, HF FAX, NAVTEX, HFDL, and an FLDIGI window with RTTY, PSK31, Olivia, MFSK, DominoEX, THOR, THROB, Hellschreiber, MT63, Packet and APRS), with a Decoder button row under the Mode buttons.
  • Receive Diversity (desktop and mobile pages), as in PhantomSDR-Plus: a second receiver somewhere else (an UberSDR, a KiwiSDR, a PhantomSDR-Plus or a classic WebSDR) follows your tuning, and the speaker plays whichever of the two hears the station better (details).
  • Audio tools in the listener's browser: Weak-signal AGC, noise reduction, two autonotch filters, squelch, soft limiter, Hi-Boost, L/R output, WAV recording.
  • Users list with each listener's country and city; clicking a listener tunes to their frequency and mode.
  • Works with DJ0MY's CATSync (Windows): your own transceiver and the WebSDR follow each other's frequency and mode, both ways.
  • Mobile page: phones are sent there automatically, with the same audio tools and an S-meter.
  • Station labels on the frequency scale, from a plain text file.
  • Chatbox working with UberSDR's WebSDR chat. The server keeps the last 20 messages in memory until it restarts.

UberSDR itself is not modified. The files are mounted into its container, UberSDR updates leave them alone, and uninstalling brings back UberSDR's own page.

2Requirements

  • A working UberSDR made with its standard installer (Docker Compose). The package expects the usual folder ~/ubersdr, with docker-compose.yml, a service called ubersdr and a container called ka9q_ubersdr. Other folders and names work too.
  • UberSDR's WebSDR server switched on, in the admin page or in config.yaml: 
    server:
  enable_websdr: true
  websdr_tcp_port: 8901
    Check that http://<your-address>:8901/ shows UberSDR's own WebSDR page before you install.
  • python3 and docker on the host. Both are already there on a normal UberSDR machine.
  • For the RADE buttons (optional): UberSDR's FreeDV extension (standard in current UberSDR) and server.enable_cors: true in its config.yaml. See section 7.

3Quick install

The package is on GitHub: github.com/sv1btl/WebSDR-emulation-for-UberSDR.

  1. Get the package on the UberSDR machine, for example in your home folder. With git: 
    git clone https://github.com/sv1btl/WebSDR-emulation-for-UberSDR.git
cd WebSDR-emulation-for-UberSDR

    Or without git, as a ZIP file:

    wget https://github.com/sv1btl/WebSDR-emulation-for-UberSDR/archive/refs/heads/main.zip
unzip main.zip
cd WebSDR-emulation-for-UberSDR-main

    Or download websdr_sv1btl_package.zip and its .sha256 file from the Releases page, check it with sha256sum -c websdr_sv1btl_package.zip.sha256, then unpack it with unzip websdr_sv1btl_package.zip && cd websdr_sv1btl_package.

  2. Run the installer. 
    bash install.sh                  # UberSDR in ~/ubersdr
bash install.sh /path/to/ubersdr # UberSDR somewhere else

    It deletes nothing. It:

    • copies websdr_sv1btl/ next to docker-compose.yml;
    • adds 6 mount lines to the ubersdr service, after saving a backup as docker-compose.yml.bak.<date>;
    • copies websdr_waterfall_calibration from UberSDR's config into station.js;
    • offers to set up the WebSDR relay for Receive Diversity, asking for its port (Enter for 8902; details);
    • asks before recreating the container. This happens once, the first time, and stops listeners' audio for about 15 seconds. Answer N to do it later with cd ~/ubersdr && docker compose up -d ubersdr;
    • runs a check, where every line should say OK.
  3. Edit your station settings in ~/ubersdr/websdr_sv1btl/sv1btl/station.js (section 4). No restart is needed.
  4. Open http://<your-address>:8901/ and press Ctrl+F5. Try the mobile page at /m.html too.

The band table

Each line is [ 'button text', lowest kHz, highest kHz, kHz the button tunes to, 'mode' ],. For example, [ '40m', 7000, 7300, 7200, 'LSB' ], suits Region 2. The range also decides which band button lights up as a listener tunes around.

The desktop page title

The browser-tab title of the desktop page comes from UberSDR itself (instance name and location in its admin page), not from station.js.

A typo in station.js does not break the page. It shows a red line, "Station settings not loaded: sv1btl/station.js is missing or has a typo". Press F12: the browser console shows the line with the error, usually a missing comma or quote.

5Station labels

The labels on the frequency scale come from websdr_sv1btl/sv1btl/stationinfo.txt, one per line, as <kHz><mode> <text>:

7074usb FT8
10136usb FT8
729am ERT Athens
14100cw NCDXF beacons

The mode is am, fm, usb, lsb or cw; clicking the label tunes there in that mode. A label whose text names a digital mode (FT8, FT4, FT2, JS8, WSPR, SSTV, FAX, NAVTEX, RTTY, PSK31, Olivia, MFSK16/32/64, DominoEX, THOR, THROB, Hell, MT63, Packet, APRS) also starts that decoder, with its own sideband and filter (desktop page); within 2 kHz of the mode's usual frequency it tunes to that frequency, "FT8<br>JT65" starts FT8, and clicking a label without a digital mode stops a running decoder. For the decoders that read the signal above the dial (FAX, NAVTEX, RTTY, PSK31, Olivia, the FLDIGI modems, Packet) the label is the signal's own frequency: 518usb NAVTEX tunes the dial to 517.50 and the display shows 518.00. Lines starting with # are comments, and <br> in the text starts a second line. The file in the package is SV1BTL's list (time signals, European broadcasters, some Athens stations), so adapt it to your area. The page reads it again on each band or zoom change, so after editing just reload.

The mode can also be a PhantomSDR-Plus markers.json mode, written the same way: ft8, ft4, ft2, js8, wspr, sstv, fax, navtex, sitor, rtty, rtty-wx, psk31, olivia, aprs, radel, radeu, morse, hfdl, drm. Then the mode alone decides what a click does, whatever the text says: 147.3rtty-wx DWD DDH47 starts the DWD weather RTTY decoder, 2174.5sitor SITOR MSI the NAVTEX / SITOR-B decoder, 7087radel FreeDV RADE on LSB, and 77.5morse DCF77 CW with its decoder, 2986hfdl the HFDL decoder. DRM takes AM (3205drm); the DRM button then decodes it. SV1BTL's file has the markers of PhantomSDR-Plus's frequencylist/mymarkers.json and decodermarkers.json in this form, after the station's own labels.

The labels appear only from a quarter of the way in on the zoom range (25–100 %); further out they would crowd the scale. To change that, edit e.zoom * 4 < e.maxzoom in sv1btl/ubersdr-compat.js (* 2 = from half zoom, or delete that line to show them at every zoom).

7How it works

UberSDR builds its WebSDR page from files in the container's /app/websdr/ folder. The package mounts five of them, plus one folder of its own, from ~/ubersdr/websdr_sv1btl/:

websdr-head.html      page <head>: styles, scripts
websdr-controls.html  desktop page body (RW3PS layout)
websdr-base.js        page logic (Twente WebSDR, with RW3PS changes)
m.html                mobile page
mobile-controls.html  mobile page body
sv1btl/               everything else, served as /sv1btl/…
  station.js          your settings
  stationinfo.txt     your labels
  ubersdr-compat.js   glue to UberSDR and all the extras
  websdr-nr.js        noise-reduction engine
  images, fonts, less.js, jQuery, guide/

UberSDR's own websdr-sound.js (Opus audio) and websdr-waterfall.js are not replaced. ubersdr-compat.js hooks into them, which is why the check script verifies them after each UberSDR update.

Editing files safely

  • Saving into the same file (nano, most GUI editors, cat > file) makes the change live at once, with no restart.
  • Replacing the file (sed -i, copying a new file over it, some vim settings) is not seen until docker restart ka9q_ubersdr. A restart stops listeners' audio for about 15 seconds.
  • Files inside sv1btl/, station.js included, are always seen at once.

Browsers cache scripts, so press Ctrl+F5 after editing a .js file. To make every visitor's browser fetch a changed ubersdr-compat.js, raise the ?v=… number after it in both websdr-head.html and mobile-controls.html.

RADE (FreeDV digital voice)

The RADEL and RADEU buttons in the Mode row decode RADE V1 on the lower or upper sideband, with a 700–2200 Hz passband (1500 Hz, the width of a RADE signal; the 1.50 kHz filter button, first in the LSB and USB filter presets, lights up). Pressing the lit button again, or any other mode button, switches it off.

UberSDR decodes RADE on the server, with its FreeDV extension (freedv-ka9q). That extension only works on a session of UberSDR's own interface, not on a WebSDR (port 8901) one. So when a listener presses RADEL or RADEU, their browser:

  1. registers a session with UberSDR's main web server (mainServer in station.js);
  2. opens an audio session there on the same frequency in LSB or USB, muted, so no audio is sent back for it;
  3. asks UberSDR to start the FreeDV decoder on it, and plays the decoded voice through the page's volume, Hi-Boost, notch and NR, while the normal audio is silenced.

Tuning on the page is followed. A status line under the Mode row shows "waiting for a RADE signal…" or "decoding", and the lit button turns green while voice is decoded.

Below it, a small FreeDV Reporter window lists the stations reported to FreeDV Reporter on the band you are on, as in UberSDR's own FreeDV panel: callsign, country, distance, frequency (a green dot when you are on it), message, TX and last RX. Stations transmitting now come first (red TX badge), then those that transmitted most recently; the TX column shows how long ago ("3m", "2h"). Clicking a station tunes to it (RADE stays on, also when the station is on another band). The window shows four rows at a time and scrolls for more.

On the mobile page, RADEL and RADEU are at the end of the mode list, with the same status line under the buttons (the reporter window is on the desktop page only).

  • Your visitors must be able to reach mainServer. The installer fills in the public address from UberSDR's instance settings (for example a …tunnel.ubersdr.org address). Without one, the page uses port 8080 of the same host; forward that port too in that case.
  • server.enable_cors: true must be set in UberSDR's config.yaml, because the page contacts another address. The installer warns if it is off.
  • Each RADE listener uses one more UberSDR session and one FreeDV decoder (freedv_extension.max_users, 15 by default).
  • The decoder reads the sideband when it starts, so switching between RADEL and RADEU restarts it. UberSDR allows one restart every 2 seconds; the page waits and retries.

IQ and DRM

The IQ and DRM buttons in the Mode row work the same way (press the lit button again, or another mode button, to switch off; the normal audio is silenced meanwhile). IQ plays the receiver's raw I/Q, ±6 kHz around the frequency (I left, Q right), from an IQ session on mainServer; ● Rec IQ in the status line saves it as a stereo WAV file. While IQ is on, an IQ Demodulators window opens below, as in PhantomSDR-Plus: up to six receivers inside the 12 kHz around the dial, each with its own mode (USB, LSB, CW, AM, DSB, FM), frequency, width, volume and pan, and a level meter; click the spectrum to move the selected one there, or turn the wheel over it (Shift = 100 Hz). Demodulators plays them, Raw I/Q the I/Q itself; the settings are kept in the browser. DRM decodes Digital Radio Mondiale with UberSDR's DRM extension on such a session: tune to the centre of the channel; the status line shows the progress, station, MER and text. A DRM schedule window opens below, as in PhantomSDR-Plus: the DRM Reception Project's broadcasts this receiver can tune (PhantomSDR-Plus's saved copy), grouped as beamed at this station's locator, on air now (nearest first), later (next 24 h) and medium wave, with Confirmed only (confirmed on air or HFCC-registered) and ⇒ Tune. Each uses one more UberSDR session.

CW decoder

While the mode is CW (the CW button, CW narrow or wide, a keyboard key or CAT software), a window opens under the Mode buttons with the decoded text. The decoder is the one from PhantomSDR-Plus (sv1btl/cw-decoder.js): it locks on the strongest steady tone in the audio, finds the speed by itself and decodes even weak or fading signals. It shows the tone it found (≈ Hz) and the speed in WPM; a line break marks a pause or a new frequency. Clear empties the window. Choosing another mode closes it.

The Pitch slider, as in PhantomSDR-Plus, sets the tone a CW signal is heard at: 500–800 Hz in 50 Hz steps, 600 Hz by default, kept in the listener's browser. Every CW filter (CW, CW narrow, CW wide, the CW bandwidth presets) is centred on it with its own width; moving the slider keeps you on the same signal and only changes its tone.

It runs in the listener's browser, on the audio the page receives (before squelch, NR and the notch filters, so muting does not stop it). Nothing extra is asked of UberSDR: no extra session, no mainServer, no enable_cors.

  • It decodes what passes the page's filter, so tune the signal into the passband (the yellow band). With several signals in a wide filter it takes the strongest; narrow the filter (CW narrow) to pick one.
  • It needs a few seconds of a signal to lock on to its speed.
  • Desktop page only.

Digital-mode decoders

A Decoder row under the Mode buttons starts one of PhantomSDR-Plus's decoders, in the listener's browser: FT8, FT4, FT2, JS8, WSPR, SSTV, FAX, NAVTEX, FLDIGI, HFDL. HFDL (aircraft ACARS messages, dumphfdl) has a list of ground stations and their frequencies (USB, the dial on the listed frequency). As in PhantomSDR-Plus, 🗺 Map shows the aircraft that reported a position in the window and ⤢ Large map in a large window you can drag and resize (⌖ Fit all, ✕ or Esc to close); positions are kept while the map is closed, and a 📍 link in the message opens one on OpenStreetMap. The FLDIGI window's list picks RTTY, PSK31, Olivia, MFSK16·32·64, DominoEX, THOR, THROB, Hellschreiber, MT63, Packet, APRS or DWD weather RTTY (PhantomSDR-Plus 5.1.0). Its window opens above "Waterfall Settings". Pressing the lit button again, or choosing AM, FM, CW or RADE, stops it; the page then returns to the band's usual mode (LSB on 40 m, CW on 30 m…; outside the amateur bands the sideband stays) with that mode's usual filter (or the preset the listener chose for it). Tuning into another band while a decoder runs keeps the decoder's own mode and filter. Only one runs at a time. Like the CW decoder they take the received audio before squelch, NR and the notch filters, and nothing extra is asked of UberSDR.

While a decoder runs, the Mode Filters' presets on the left are replaced by Decoder Filters' presets: one button per decoder with its filter width (FT8, FT4, FT2 and JS8 2.90 kHz, WSPR 400 Hz, SSTV 1.50 kHz, FAX 1.60 kHz, NAVTEX 500 Hz, HFDL 2.60 kHz; FLDIGI follows its list: RTTY 300 Hz, DWD weather 593 Hz, PSK31 200 Hz, the other modes their bandwidth plus a margin). A button sets that decoder's sideband and filter; the one in use is lit. The Mode presets come back when the decoder stops.

SNR, dBm, dBµV and NF readouts

  • The readouts sit in a row over the S-meter, in PhantomSDR-Plus's order, each in its own fixed cell and colour: dBm cyan, dBµV green, SNR yellow, NF red; the numbers themselves are a very light grey. The MUTED, SQL, ANF1, ANF2, NR and AGC lights are in a row under the S-meter scale (lit: MUTED red, SQL orange, the others green), with a fixed place at its right end that shows the digital mode in use in bold yellow (FT8, JS8, WSPR, SSTV, FAX, NAVTEX, the FLDIGI mode such as RTTY or PSK31, or RADE) and stays empty otherwise.
  • SNR is measured on the waterfall, the way PhantomSDR-Plus does it: the noise is the quietest 3 kHz stretch of the visible span (the median of each stretch, the passband left out), rescanned every second; the signal is the strongest point in the passband; SNR is the difference in dB, never below 0, smoothed a little. A steady carrier (AM) no longer reads 0 dB, and pauses in speech are not needed. After a band change or zoom it takes a second or two to settle.
  • dBm is the current S-meter reading, with the per-band S-meter offsets of websdr-base.js applied.
  • dBµV is dBm + 107 (into 50 Ω).
  • NF is the noise floor in dBm: dBm minus SNR, so it always agrees with the SNR figure.
  • A readout shows -- while there is nothing to show (no signal reading yet; NF also until the first SNR measurement). Unlike PhantomSDR-Plus, there is no extra +5 dB display offset: the figures follow this receiver's S-meter calibration.
  • The grey noise marker on the S-meter bar still works the original way (the lowest reading over a few seconds), so it can differ from NF.
  • The SNR measurement is in sv1btl/ubersdr-compat.js (snrUpdate); the readouts are filled in by websdr-base.js. Desktop page only.

Frequency keypad

A click anywhere in the black frame with the frequency display, the magic eye and the S-meter opens a number pad over the page, so a frequency can be entered with the mouse or a finger as well as the keyboard.

  • The pad has the keys 0–9, a decimal point ., ⌫ (delete the last digit), Clear, Cancel and Enter. The number is shown in the display at its top.
  • Type the frequency in kHz, as in the frequency field: 7074, 14074.5, 198. Only digits and one decimal point are accepted (up to 9 digits); a number starting with the point gets a 0 in front.
  • Enter tunes there and closes the pad; the mode follows the band plan, as when the frequency is typed in the frequency field (LSB on 40 m, USB on 20 m…). An empty entry or 0 is ignored. Cancel, a click outside the pad or Esc closes it without tuning.
  • The computer keyboard works while the pad is open: digits (also the numeric keypad), . or ,, Backspace, Delete (clear), Enter and Esc. The page's one-key shortcuts (M for mute, arrows for tuning…) are off until it closes. On a phone or tablet the pad does not bring up the on-screen keyboard.
  • Digit tuning stays as it was: the mouse wheel over a digit, a left click on a digit (up) and a right click (down) step that digit and do not open the pad. A click beside the digits opens the pad (it used to put a typing cursor in the frequency field). The G key still empties the frequency field for typing.
  • The pad is at the end of websdr-controls.html (#freqpad, functions sv1btl_freqpopup_open and sv1btl_freqpad_key); the frame that opens it is #radiodisplay. It is dark in both themes, with the dark theme's blue on Enter. Desktop page only.

Waterfall and spectrum

The waterfall data comes from UberSDR and is drawn by the standard WebSDR waterfall script; the spectrum is built in the browser from the newest waterfall line. From PhantomSDR-Plus only their look is taken (colour map and spectrum style), while the decoders are PhantomSDR-Plus's own code. With spectrum + waterfall, the dashed line that follows the mouse runs down through the waterfall as well, as in PhantomSDR-Plus.

3D spectrum. The 3D switch next to "Tube & Waterfall & DSP & Audio" shows the spectrum in relief, as in PhantomSDR-Plus: frequency across, the last 320 lines going back into the screen, level as height. It takes the place and size of the 2D spectrum (with Type = waterfall, switching it on sets Type to spectrum + waterfall). It shows exactly what the waterfall shows: the same levels in the same colours, through the waterfall's brightness and contrast, so Auto brightness (or the sliders) changes the waterfall and the whole 3D picture alike. dBFS marks on the right, seconds back on the left; ⚙ sets angle and depth. With spectrum + waterfall, hovering shows the frequency and a click tunes there (on an older line: that line's frequency). It needs WebGL2; the choice is kept in the visitor's browser.

Auto brightness reacts at once after a page load, zoom or band change (first setting after one new line, then with every line for the first twelve), then calmly: a check every 4 s with small, eased steps.

The Band button in Waterfall Settings follows the band plan: it zooms to the whole band you are in and sets that band's mode, keeping the frequency shown (40 m 7000–7200 LSB, 30 m CW, 41 m broadcast 7205–7605 AM…). The amateur bands come from the band table, the rest from the page's band-plan table (modeperfreq in websdr-base.js). A running decoder stops. Outside both it zooms ±100 kHz as before.

Receive Diversity

Combine this receiver with a second receiver somewhere else and listen to whichever of the two has the better signal at the moment, as PhantomSDR-Plus does. When one site is in a fade, the other usually is not, so you keep copy through it; two sites also have different local noise. It is selection, with a 30 ms crossfade at each switch, not a sum of the two signals: two distant receivers hear the station over different paths, with unrelated phase. So it buys continuity, not a stronger signal.

  • The Receive Diversity panel is in the middle column, just above the "Switch to another WebSDR" links, collapsed. Click it to open it, choose what the second receiver is, type its address and press Start: an UberSDR by its normal web address (sdr.example.org, not port 8073), a KiwiSDR as host:8073, a PhantomSDR+ as host:8900, a WebSDR as host:8901 (through this station's relay, see below). Nothing has to be set up on the other receiver.
  • Tune as usual: the second receiver follows the frequency, mode and filter by itself.
  • You listen 1–3 seconds behind real time, because the earlier stream is delayed to match the later one. Lining the two streams up takes about 15–30 seconds of signal; meanwhile they are paired by arrival and the better one is already chosen (Ready (unaligned)). Both receivers must hear the station: on a band with only noise at both ends they never line up, and should not.
  • The word beside the title: off, Please wait… (amber: connecting or still aligning), Ready (green), or the error (red). The dot shows which site you hear: green this receiver, cyan the second one. The table shows the link, the measured delay (aligned), the correlation, the remote audio arriving, both SNR figures and the number of switches.
  • Remote SNR trim (−15 … +15 dB) is added to the second receiver's SNR before the two are compared: + favours it, − this one. +15 and −15 force one site, to hear it alone. Start at 0; a KiwiSDR may want a few dB +. If it flips back and forth constantly, move the trim a little.
  • ☰ keeps every receiver used, per type, in the visitor's browser: give one a name, edit it, drag it up or down (or use ▲▼) to change the order, remove it, open its own page (🌍), and export or import all the lists as a file.
  • The CW and digital decoders keep using this receiver (a switch in the middle of a slot would spoil a decode); diversity feeds the speaker only. RADE also uses this receiver.
  • Weak-signal AGC is switched off when you press Start and back on when you press Stop.
  • A session uses one listener slot on the other receiver for as long as it runs; please be considerate with volunteers' receivers.
  • The panel is sv1btl/diversity-ui.js; the combiner and the receiver connections are PhantomSDR-Plus's own files in sv1btl/psdr/ (diversity.js, uberSource.js, kiwiSource.js, remoteSource.js, webSdrSource.js, webSdrCodec.js, diversityList.js), with PhantomSDR-Plus's audio module (psdr/modules/phantomsdrdsp_bg.*) for FLAC from a PhantomSDR+.
  • On the mobile page it is a section of its own, Receive Diversity:, just under the RADE status line (above Memories): tap it to open it. Type, address, Start/Stop, the trim, the status table and the saved receivers (tap one to use it, 🌍 its own page, ✕ remove, export and import) work as on the desktop; naming and reordering are on the desktop page. The saved list is kept per browser, so a phone starts empty: export it on the desktop and import the file on the phone.

The WebSDR relay (for example port 8902)

A classic WebSDR (PA3FWM's software) accepts its audio only from its own page, and a browser cannot pretend otherwise. So the connection goes through a small relay program on this server, PhantomSDR-Plus's websdr_relay.py, in websdr_sv1btl/relay/, run as a Docker container on a port of its own. Listeners' browsers connect to it directly, on that port of the same address as the page.

install.sh offers to set it up (answer y). It asks for:

  • your callsign (an e-mail address too, if you like) and your page's public address (offered from UberSDR's own settings). Both are sent to each WebSDR as the relay's User-Agent, so its operator knows who is connecting;
  • the port for the relay: press Enter for 8902, or type another free one (1024–65535, not the WebSDR port). The installer writes it into relay/websdr_relay.json and into station.js (diversityRelayPort), so the page finds the relay there.

It then builds and starts the container (it starts again by itself after a reboot) and checks that it answers. On an upgrade the relay's settings are kept and the container is restarted with the new files.

The relay's port (e.g. 8902) must be forwarded (opened) on your router to the UberSDR machine, TCP, just like 8901. Without it, WebSDR diversity works only inside your own network. UberSDR, KiwiSDR and PhantomSDR+ partners do not need it. Check it with http://<your-address>:8902/status from outside your network (a phone on mobile data).

By hand instead (port 8902 in this example): set "site", "operator" and "port" in websdr_sv1btl/relay/websdr_relay.json, then

docker build -t websdr-relay ~/ubersdr/websdr_sv1btl/relay
docker run -d --name websdr_relay --restart unless-stopped -p 8902:8902 \
  -v ~/ubersdr/websdr_sv1btl/relay:/app:ro websdr-relay

For another port, use it in both -p numbers and in diversityRelayPort in station.js. After editing the settings: docker restart websdr_relay.

The relay allows 10 sessions to any one WebSDR and 60 in all, passes on only tuning commands, and refuses private addresses. The other WebSDR's user list shows the session as "<callsign> diversity". WebSDR operators added the Origin check on purpose: keep the limits and stop if an operator asks. uninstall.sh offers to remove the relay container.

Page size, look and dark theme

  • Fits the window. The desktop page is scaled to 90% of the width of the browser window, centred (0.5× to 3×; FIT_SHARE in ubersdr-compat.js), so it suits a 1024 px laptop screen as well as a Full HD, 2K or 4K monitor, and follows when the window is resized. Clicks, drags, the mouse wheel and the frequency digits stay exact. Add ?nofit to the address for the old fixed size.
  • Dark theme. The Light GUI / Dark GUI switch next to Auto brightness turns dark: the page header, the WebSDR Information panel, the Waterfall / Keyboard Control / Background image boxes, the control panel (buttons, lists, switches, sliders), the RADE, CW and decoder windows, the signal strength plot, the users bar and the chat box. The radio display with the S-meter and the waterfall stay as they are. Off (the original light look) is the default; each visitor's choice is kept in their browser.
  • Colours. Light theme: the original teal for selected buttons, switches, radio buttons and sliders. Dark theme: blue (#3a6db5) for all of them. Without the background image the page background is very dark blue (#0a1a3a). Links are blue (#0645ad) in the light theme and keep their light blue in the dark theme; in both they turn red under the mouse (the cyan links at the bottom of the page keep their colour).
  • Sliders and on/off switches have the same small 3D knob, in both themes (in the dark theme with a deeper shadow and a light edge so it stands out); slider tracks and switch grooves look slightly sunken. In the dark theme the "Switch to" buttons for other WebSDRs are raised grey buttons too, like the other dark buttons.
  • Desktop page only; the mobile page keeps its own look.

What listeners' browsers contact

Your UberSDR for the page, audio and waterfall, and its main web server (mainServer) only while RADE, IQ or DRM is on, tile.openstreetmap.org for the map tiles only while the HFDL map is open, and the second receiver chosen in Receive Diversity only while that runs (for a WebSDR, this station's relay on port 8902 instead). Also get.geojs.io (with ipwho.is as a fallback) once a day per visitor, to find the visitor's own country and city for the users list. Section 13 shows how to switch that off.

8After an UberSDR update

UberSDR's updater only adds missing services to docker-compose.yml and never changes the ubersdr service, so the mount lines stay. After each update, run:

bash ~/ubersdr/websdr_sv1btl/check-after-update.sh

If every line says OK, everything is in place. A FAIL line says what is wrong. The usual case is missing mount lines; compose-mounts.txt in the package has them. The other is "websdr-sound.js changed shape", meaning a new UberSDR renamed something the audio extras use. The page still plays; please report it on GitHub Issues.

With another folder or container name:

UBERSDR_DIR=/path/to/ubersdr CONTAINER=my_container URL=http://localhost:8901 \
  bash /path/to/ubersdr/websdr_sv1btl/check-after-update.sh

9Upgrading to a newer package

Get the new version and run its install.sh again:

cd WebSDR-emulation-for-UberSDR   # the folder you cloned
git pull
bash install.sh

Without git, download and unpack the new ZIP or release archive and run its install.sh. The installer saves the current folder as websdr_sv1btl.bak.<date>, writes the new files in place (live at once, no restart), and keeps your station.js and stationinfo.txt. Settings that are new in the version are added to your station.js with their default value; your own values are not changed, and the installer lists what it added.

10Uninstalling

bash uninstall.sh                  # or: bash uninstall.sh /path/to/ubersdr

This removes the 6 mount lines (keeping docker-compose.yml.bak.<date>) and, after asking, recreates the container, so UberSDR's own WebSDR page is back. It also offers to remove the WebSDR relay container, if there is one. The websdr_sv1btl folder stays; delete it by hand if you want.

11Manual installation

  1. Copy the websdr_sv1btl folder next to docker-compose.yml.
  2. Under services: → ubersdr: → volumes:, add these lines, indented like the ones already there: 
          - ./websdr_sv1btl/websdr-head.html:/app/websdr/websdr-head.html
      - ./websdr_sv1btl/websdr-controls.html:/app/websdr/websdr-controls.html
      - ./websdr_sv1btl/websdr-base.js:/app/websdr/websdr-base.js
      - ./websdr_sv1btl/m.html:/app/websdr/m.html
      - ./websdr_sv1btl/mobile-controls.html:/app/websdr/mobile-controls.html
      - ./websdr_sv1btl/sv1btl:/app/websdr/sv1btl
  3. Set waterfallCalibration in sv1btl/station.js to the value this prints: 
    docker exec ka9q_ubersdr grep websdr_waterfall_calibration /app/config/config.yaml
  4. Apply it with cd ~/ubersdr && docker compose up -d ubersdr, then check it with bash ~/ubersdr/websdr_sv1btl/check-after-update.sh.
